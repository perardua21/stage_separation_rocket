# 2단 로켓 FreeRTOS 비행 로직과 검증 계획

## 목적과 현재 결론

이 로직은 제공된 상태머신 설계서를 실행 가능한 독립 코어로 옮기고 ESP32-S3
FreeRTOS 태스크에 연결한다. 현재 산출물은 센서, 큐, 상태전이, 로그,
텔레메트리를 검증하는 실험용 벤치 펌웨어다. PCB에 비행 필수 안전 입력과
충분한 출력 채널이 없으므로 액추에이터 출력은 항상 차단된다.

## 데이터 소유권과 태스크 경계

상태머신 태스크만 현재 상태, 전이 기준 시각, 연속 샘플 카운터, 최고고도를
변경한다. 각 센서 태스크는 `SensorMessage`를 센서 큐에 넣고, 콘솔 태스크는
`ControlCommand`를 명령 큐에 넣는다. 상태머신은 한 샘플을 처리한 뒤 불변
`FlightSnapshot` 복사본을 로그 큐와 최신 텔레메트리 큐에 각각 넣는다.
액추에이터 요청은 별도 큐를 거쳐 안전 태스크가 처리한다.

이 구조에서 큐는 상태 저장소를 대신하지 않는다. 상태를 여러 태스크가 직접
수정하면 전이 판단 중간에 값이 바뀔 수 있다. 단일 소유 상태와 메시지 큐를
조합해야 판단의 순서와 로그 프레임의 일관성을 동시에 보장할 수 있다.

센서 장치 접근도 레퍼런스 코드와 같은 계층으로 분리한다. `Bno085Hal`과
`Bmp388Hal`은 버스 설정, 장치 초기화, 레지스터/라이브러리 읽기만 담당한다.
`ImuTask`와 `BarometerTask`는 HAL 인터페이스를 주입받아 자세 기준, 속도 적분,
기압 기준고도와 필터를 계산한 뒤 `SensorMessage`를 큐에 발행한다. 따라서 센서
태스크에는 Adafruit 장치 객체나 SPI/I2C 읽기 호출이 들어가지 않는다.

## 입력과 단위

| 입력 | 단위 | 생산 주기 | 용도 |
|---|---:|---:|---|
| 가속도 크기 | G | 100 Hz | 발사, 연소종료, 점화 확인 |
| 필터 상대고도 | m | 20 Hz | 점화 허용 고도, 정점, 착지 |
| 수직속도 | m/s | 20 Hz | 정점 하강 확인 |
| 초기 종축 대비 기울기 | degree | 100 Hz | 2단 점화 금지 판단 |
| 종축 선형가속도 적분속도 | m/s | 100 Hz | 2단 점화 허용 판단 |
| 배터리 전압 | V | 100 Hz 표본 | 로그와 텔레메트리 |
| 분리 감지 | boolean | 사건 | 부스터 COAST, 서스테이너 SEPARATED |
| 아밍 및 해제 명령 | 사건 | 비동기 | SAFE와 ARMED 전이 |

BNO085 자세를 이용해 PCB `+X` 축을 초기 세계좌표계의 수직 기준으로 잡고,
선형가속도를 그 축에 투영해 속도를 적분한다. 실제 기구 조립에서 `+X`가 로켓
종축이라는 근거가 아직 없으므로 이 계산은 벤치 검증 전까지 실험용이다.

## 허용 상태와 금지 상태

센서 수집은 모든 상태에서 허용한다. 로그는 현재 프로토타입에서 항상 생성되며
비행 로직 검증에 사용한다. 실제 요구사항의 ARMED 이후 기록 정책은 SD 파일
용량과 발사 전 버퍼 시험 후 적용할 수 있다.

2단 점화 요청은 서스테이너 `SEPARATED`에서 다섯 조건을 모두 만족할 때만
생성한다. `SAFE`, `ARMED`, `RIDE`, `RECOVERY`, `APOGEE`, `DEPLOY`,
`GROUND`에서는 금지한다. `RECOVERY` 진입 후 점화 금지는 영구적이다.
패킷 수신이나 시리얼 파싱은 액추에이터 GPIO를 직접 바꾸지 않는다.

## 임계값과 출처

| 판단 | 값 | 출처 |
|---|---|---|
| 발사 | 2.0 G 이상 5샘플 | 제공 설계서 OpenRocket 기준 |
| 1단 연소종료 | 2.0 G 이하 5샘플, T0+0.5 s 이후 | 제공 설계서 |
| 1단 연소 강제전이 | T0+1.3 s | 제공 설계서, 시뮬 연소시간+0.3 s |
| 분리 타임아웃 | T0+2.5 s | 제공 설계서 |
| 점화 창 | T_sep+0.5 s부터 +1.5 s | 제공 설계서 |
| 점화 기울기 | 20 degree 미만 | 제공 설계서의 팀 결정값 |
| 점화 속도 | 30 m/s 초과 | 제공 설계서 OpenRocket 57 m/s 대비값 |
| 점화 고도 | 45 m 이상 | 제공 설계서, 분리고도 65 m의 70% |
| 점화 확인 | 3.0 G 이상 5샘플, 1.0 s 이내 | 제공 설계서 |
| 2단 연소종료 | 2.0 G 이하 5샘플, T_ign+1.0 s 이후 | 제공 설계서 |
| 2단 연소 강제전이 | T_ign+2.2 s | 제공 설계서 |
| 정점 | 최고고도보다 3 m 하강, 수직속도 0 이하, 5샘플 | 제공 설계서 |
| 부스터 정점 허용 및 강제 | T0+3.5 s, T0+6.2 s | 제공 설계서 |
| 서스테이너 정점 허용 및 강제 | T_ign+6.0 s, T_ign+12.0 s | 제공 설계서 |
| 사출 펄스 | 채널당 1.0 s | 제공 설계서, 작년 방식 |
| 착지 | 5 s 고도 범위 2 m 미만 | 제공 설계서 |
| 착지 강제전이 | 부스터 40 s, 서스테이너 140 s | 제공 설계서 |

RECOVERY 강제 정점 시각은 설계서가 추가 시뮬레이션을 요구한다. 값을 만들지
않았으며, RECOVERY에서는 기압 정점 조건만 사용한다.

## 출력 채널 정책

부스터에서는 채널 1을 주 사출, 채널 2를 백업 사출 요청으로 사용한다. 설계서의
모터 지연 장약 분리 방식을 전제로 분리 출력은 사용하지 않는다.

서스테이너에서는 채널 1을 2단 점화, 채널 2를 주 사출 요청으로 사용한다.
점화 채널을 정점에서 백업 사출로 재사용하지 않는다. 잘못 연결된 점화기에
재전류가 흐를 수 있기 때문이다. 따라서 현재 PCB에서는 백업 사출을 구현할 수
없다.

모든 요청은 액추에이터 큐에 기록되지만 `NURA_BENCH_SAFE` 빌드의 태스크는
`HEAT_ARM`, `HEAT_IN1`, `HEAT_IN2`를 LOW로 유지한다. 비행 출력용 빌드 경로는
소스 수준에서 컴파일 오류로 막혀 있다.

## 고려한 실패 모드와 폴백

| 실패 | 동작 |
|---|---|
| 분리 미확인 | `RECOVERY`, 이유 `NO_SEP`, 점화 영구 금지 |
| 기울기 20 degree 이상 | 즉시 `RECOVERY`, 이유 `TILT` |
| 점화 창에서 속도 또는 고도 부족 | `RECOVERY`, `LOW_VEL` 또는 `LOW_ALT` |
| 점화 명령 후 1 s 안에 3 G 미확인 | 출력 OFF 요청, `RECOVERY`, `NO_IGN`, 재점화 없음 |
| 센서 큐 지연 | 새 샘플을 버리지 않고 큐가 찬 경우 해당 생성 주기만 누락 |
| 로그 큐 포화 | 상태머신은 멈추지 않고 누락 카운터를 텔레메트리에 포함 |
| 텔레메트리 지연 | 길이 1 큐의 프레임을 최신값으로 교체 |
| 액추에이터 큐 포화 | 모든 출력 LOW |
| 리셋 후 고도 20 m 이상 | 아직 미구현, 기준고도 영속 저장 설계 필요 |
| BNO085 또는 BMP388 초기화 실패 | INIT에 머무름, 향후 명시적 고장 비트 추가 필요 |

## 검증 계획

1. 호스트 단위시험에서 부스터 및 서스테이너 정상 경로, 분리 실패, 기울기
   금지를 확인한다.
2. 센서 없이 큐 부하 시험을 실행해 로그 지연이 상태머신 주기를 막지 않는지
   확인한다.
3. PCB에 점화기 대신 LED와 전류 제한 저항을 연결하되 벤치 빌드에서는 실제로
   켜지지 않는지 확인한다.
4. BNO085 PCB `+X`와 로켓 종축을 실제 장착도에서 확인하고 0, 10, 20 degree
   지그로 기울기 오차를 측정한다.
5. 알려진 높이 변화로 BMP388 상대고도와 3 m 하강 판정의 잡음 여유를 측정한다.
6. OpenRocket CSV 재생 시험을 추가해 모든 기준 시각과 원인 코드를 비교한다.
7. PCB 수정 후 물리 아밍, 분리 입력, 연속성, 세 출력 채널을 하드웨어 통합
   시험한다.
8. 점화기 대신 전력 저항을 사용해 1 s 펄스와 공통 차단의 독립성을 시험한다.

비행 허용 기준은 위 시험 통과, RECOVERY 시뮬레이션 완료, PCB 안전 입력 보강,
코드 리뷰, 실제 부하 지상시험을 모두 만족하는 것이다.
